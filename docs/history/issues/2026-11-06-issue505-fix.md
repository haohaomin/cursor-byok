# Issue #505：保留多个 reasoning signature

> 状态：源码修复已完成，自动化测试通过；真实 Cursor、原作者网关和真实签名数据尚未验收。

上游 [Issue #505](https://github.com/leookun/cursor-byok/issues/505) 描述同一助手消息包含多个 reasoning signature 时恢复失败。当前修复覆盖两条丢失路径：checkpoint 解码不再拒绝第二个签名，模型流收到多个 `ProviderReplayState` 时也不再覆盖或报错。

## 改动路径

```text
Cursor checkpoint
    ↓
server/src/cursor/checkpoint/messages/decode.rs
    # 收集每个 reasoning 块的文本与 signature；按输入顺序保存
    ↓
server/src/model/message.rs
    # 合并同一 provider 的多个 replay state
    ↓
server/src/run/model_cycle.rs
    # 一轮模型流允许多个 ProviderReplayState
    ↓
server/src/cursor/checkpoint/messages/encode.rs
    # opaque signature 逐个写回；已知 provider state 按 provider 结构合并回放
```

主要行为：

- 多个不透明 Cursor signature 保存为有序 `signatures`，同时保存已知的每段 reasoning 文本。
- 多个 Anthropic `blocks`、OpenAI Responses `items` 按原顺序拼接。
- 多个 OpenAI Chat `reasoning_content` 按顺序拼接。
- 插件只提供多个 opaque signature、没有文本边界时，累计 reasoning 保留在第一段，后续签名仍按顺序写回。
- 混合或未知 provider state 不会静默丢弃后续状态，而是保留为顺序序列并使用 BYOK replay envelope。
