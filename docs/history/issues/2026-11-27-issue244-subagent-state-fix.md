# Issue #244：子代理完成状态的保存与恢复

日期：2026-11-27–28。基线 `cc069e8959a3b9a8b32dd5fd86d0dff957b68238`（v1.2.14 后文档提交）。这是[通知接收修复](2026-11-27-issue244-notifications-fix.md)后的独立缺口，不代表完整项目编排已完成。

## 问题与复现

此前普通完成通知能唤醒模型，但 `subagent_runs_by_parent_tool_call_id` 仍为 Backgrounded；record-only 直接确认，不记录运行状态。因此任务结束后卡片数据仍可显示后台运行，重启也无法恢复完成记录。

三个初始用例均失败：普通完成的状态仍为 2（期望 Success=3），只记录通知没有更新检查点，重启后找不到完成结果。补充历史压缩回归还发现，仅合并目标检查点的祖先不能解决问题：下一条用户消息从 Cursor 历史导入新分支时，会读不到旧分支上记录的终态。

Cursor 3.31.15 安装包的静态实现先记录子代理状态，再决定是否唤醒模型；对旧终态使用严格时间比较，后续检查点保留更新的终态。静态源码身份、锚点与失败日志摘要见[证据](2026-11-27-issue244-subagent-state-evidence.json)。这些是已发布程序的静态契约，不是当前 Cursor 窗口的实机运行观察。

## 实现

```text
server/
├── migrations/0013_add_cursor_subagent_runs.sql # 会话内按父工具调用保存子代理状态
├── src/store/cursor_checkpoints.rs             # 状态记录和检查点的原子读改写
├── src/cursor/checkpoint/subagents.rs          # 通知归并、终态保护和 protobuf 编解码
├── src/cursor/checkpoint/worker.rs             # 所有检查点写入折叠已保存终态
├── src/cursor/conversation/registry.rs         # 空闲发布与最终发布的运行所有权边界
├── src/cursor/conversation/runtime.rs          # 接入通知记录与结束刷新
├── src/cursor/goals/action.rs                  # 续跑确认、暂停与清除保留终态
├── src/cursor/transport/handle.rs              # 保留已发送呈现，取消/失败补发不倒退历史
└── tests/conversation_delivery/subagent_state.rs # 通知、重启、并发和历史回归
```

```text
完成通知 → BEGIN IMMEDIATE
          → 读当前检查点及会话内运行记录 → 按原因/时间归并
          → 同事务保存运行记录和检查点 → COMMIT
          → record-only：不生成模型消息或 Run
          → 可见通知：沿用现有去重和自动续跑

父 Run 继续/导入历史/压缩 → 保存检查点时折叠会话内终态
父 Run 活跃：侧通道不覆盖流式呈现
父 Run 结束：持有运行协调锁，刷新最终状态并发布，再释放所有权
父 Run 空闲：通知直接发布当前检查点，再确认结束
```

运行状态属于会话，与规范模型历史的分支分别保存。两个存储入口分别更新指定检查点或事务内选出的当前检查点；存储层只处理字节和 SQL，原生状态语义集中在 `checkpoint/subagents.rs`。新增前向迁移，不修改已应用迁移，不改变模型历史或供应商协议。

归并要求有效的父工具调用 ID；Shell、进度和 WorkerMessage 不误记为子代理完成。未指定状态的待操作通知保留原状态；更旧的终态通知不能覆盖新结果，等时更新允许生效。旧父检查点也不能抹掉带时间的待操作/转交通知。标题、详情、输出和已知子代理环境/转录路径按原生规则保留。
