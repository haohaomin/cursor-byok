# 异步导入的焦点恢复

2026-11-06 在 main `1de8e4258c7a37e421fe0fc2d2e19807cbc729ed` 复现：设置页与空模型页两个导入入口，在取消、Esc、预览失败和导入成功后均将焦点留在 BODY。8 组基线全部失败。此问题是 #370 滚动验收中记录的独立边界；本次候选已在合入 PR #30 的 main `574f2f4f3da4eef6b980b70931a2d256d81a8952` 上复测。

## 原因与参考

导入入口在预览请求期间禁用按钮。弹窗等待请求返回后才打开，此时只记录 `document.activeElement` 已无法可靠识别来源。成功导入还可能移除空模型页的入口，因此仅保存旧 DOM 节点不足以覆盖完整流程。

上游 PR 的 `focus` 搜索结果没有直接对应修复，标题 `modal` 搜索没有结果。当前依赖没有现成的对话框焦点管理层，沿用已有 Modal 生命周期及 DOM focus API。[WAI-ARIA 对话框规范](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)要求关闭后返回来源；来源消失时，应选择后续操作中合理的焦点位置。本页采用已有工具栏“添加模型”作为导入成功后的落点。

## 职责与时序

```text
apps/desktop/src/
├── features/models/
│   ├── LegacyModelImport.tsx    # 104 行；记录点击来源，提供关闭后的焦点目标，处理预览失败
│   ├── CursorGates.tsx          # 43 行；将真实按钮点击事件传递给导入流程
│   └── CursorSettingsPage.tsx   # 421 行；提供成功导入后持续存在的“添加模型”按钮
└── shared/ui/
    ├── ConfirmDialog.tsx        # 35 行；将业务提供的焦点目标交给 Modal
    └── Modal.tsx                # 115 行；保持弹窗内焦点，仅在关闭时返回外部目标
```

行数包含注释与空行，不含测试或生成代码。未新增依赖、全局焦点状态、轮询或业务 API。

```text
点击来源按钮 → 保存 event.currentTarget → 请求预览
  ├── 失败：按钮恢复可用后，若焦点丢失到 BODY，返回来源
  │         用户已转移到其他控件时保持其选择
  └── 成功：打开弹窗 → 确认按钮获得焦点
              ├── 取消/Esc → 返回来源
              └── 导入中 → 同一弹窗内保持焦点，禁止重复提交/关闭
                    ├── 失败 → 焦点回到可重试的确认按钮
                    └── 成功 → 关闭弹窗
                          ├── 来源仍存在 → 返回来源
                          └── 空状态入口消失 → 工具栏“添加模型”
```

Modal 将关闭生命周期与加载状态下的内部焦点调整分开。`busy` 变化不会执行关闭清理；已有可用控件上的焦点不被重置。关闭时再解析业务给出的目标，避免在异步更新提交到 DOM 前判断入口是否仍存在。普通同步弹窗继续由其自身记录打开前的焦点。

## 实测

- 两入口 × 鼠标取消、键盘 Esc、预览失败、成功，共 8 组全部通过；保留原失败结果。
- 首轮候选补测发现导入中确认按钮禁用也会使焦点掉到 BODY，失败后仍未恢复；补齐 Modal 内部焦点维护后，此失败转为通过。
- 初始确认焦点、Tab/Shift+Tab 循环、加载中 Esc 不关闭、加载中焦点保留、错误后恢复确认、错误后取消返回来源均通过。
- 预览失败时，若用户已聚焦语言控件，不抢走焦点；未传入自定义目标的“清理存储”同步弹窗取消后仍返回原按钮，未执行清理。
- 导入失败后按 Enter 重试成功：总计一次 GET、两次 POST；加载中连续 Enter/Esc 没有重复请求，成功后移到工具栏“添加模型”。
- `npm run check` 和 Tauri debug/no-bundle 的实际结果记录在[结构化证据](2026-11-06-import-dialog-focus-evidence.json)。本机构建沿用 `profile.dev.package.sqlx-macros.strip="none"`，未修改仓库工具链。
