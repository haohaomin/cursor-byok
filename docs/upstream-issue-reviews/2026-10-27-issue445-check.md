## 失败基线

[可复现探针](reproductions/issue445_refresh_baseline.ts) 在基线 checkout 中与原有 `grok_test.ts` 一起执行：原有 **10 项通过**，新增 **2 项失败**。

| 场景 | 实际结果 |
| --- | --- |
| access token 已过期，refresh token 有效，刷新账号 | 只请求 billing，收到 401 后将账号设为 invalid；没有请求 token grant |
| 同一账号发起模型调用 | 只请求 chat/completions，收到 401 后返回 resource-error；没有续期或恢复输出 |

这是插件函数边界的失败探针。候选改为宿主先执行 `resource.prepare`，因此不能将“直接调用插件函数”的同一探针作为候选端到端验收；需要补宿主调用链测试。

## 当前候选与已修正问题

```text
server/
├── plugins/build-in/grok-auth/
│   ├── resources.ts                 # 判断到期、交换与分类续期结果
│   ├── oauth.ts                     # 保存登录响应给出的有效期
│   ├── provider.ts                  # 输出前 401 交给宿主处理
│   └── refresh_test.ts              # 使用模拟网络验证授权与额度边界
└── src/plugin/
    ├── registry.rs                  # 同账号串行准备、保存轮换凭据及有限重试
    ├── registry/reset.rs            # 重置时结束生命周期并清理凭据状态
    ├── state.rs                     # 串行修改与旧快照回写检查
    ├── data.rs                      # 原子替换凭据文件
    └── sdk/                         # 插件准备能力与 auth-error 协议
```

原补丁与当前 CI / registry 有冲突，按当前重置、取消和 SQLite 原生测试要求适配。原补丁中的 Grok 思考强度映射与续期无关，本轮未采用；不据此宣称支持新的 reasoning 参数。

最初两项真实 Deno 宿主测试因 macOS `/var` 与 `/private/var` 临时目录别名触发读取权限不匹配，在加载测试插件时失败。测试夹具统一规范路径后通过；这两项失败不能算续期算法缺陷。

进一步增加重置断言，实测发现候选在插件 reset 后仍保留 `pending_preparations` 中待保存的轮换凭据。失败已先记录，随后补齐清理，并让脱离模型请求的准备任务持有当前生命周期保护、响应插件重置取消。模型请求取消仍允许已经启动的凭据更新完成。
