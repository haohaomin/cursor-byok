# Issue #449：子代理模型说明使用客户端提供的名单

原报告：[leookun/cursor-byok#449](https://github.com/leookun/cursor-byok/issues/449)。关注实际 Cursor 子代理工作流，不涉及供应商协议兼容。

## 问题与修复

Task 工具说明曾写死 inherit 和五个官方模型，并要求遇到不在列表里的模型就跳过子代理调用。用户在聊天里指定自己的模型时，主模型可能在发起 Task 之前就误判不可用。Cursor 设置中的模型仍可正常执行；本次修复的是主模型获得的选择信息。

删除旧名单，改为引用最新 `<subagent_models>` 上下文。读取 `AgentRunRequest.selected_subagent_models`、`selected_subagent_model_details` 中的模型 ID 与显示名称，排序去重后投影到上下文，不传入凭据。还显示当前执行层采用的首个 subagent override，明确 Cursor 设置优先于 Task 的 model 参数。

```text
Cursor AgentRunRequest
  ├─ selected_subagent_models / selected_subagent_model_details
  └─ subagent_model_overrides
       ↓
server/src/cursor/compile/model.rs          # 编译模型名单及当前设置
       ↓
server/src/cursor/compile/break_messages.rs # 作为 request-context 消息追加和去重
       ↓
provider 历史与 checkpoint                 # 名单变化追加消息，已有前缀不改写
       ↓
主模型读取 Task 说明与最新模型上下文
       ↓
server/src/cursor/tools/runtime.rs         # 原执行优先级不变：设置覆盖 > 显式 Task 模型 > 父模型
       ↓
Cursor 执行子代理
```

`server/prompt/cursor/tools.json` 只保存稳定的选择规则；不随名单变化改写工具定义。未移动、拆分或删除代码模块；删除的是工具说明里的过期名单。未新增配置、协议字段或数据库结构。

空名单明确表示客户端未提供名单，不能据此认定子代理或自定义模型不可用。名单从 A→B→A 或清空时追加新上下文，相同名单不重复追加，历史与检查点保留原消息身份。正式使用仍以客户端实际传入的信息为准。

- 修复前新增的真实 Cursor transport→编译→provider 请求捕获测试失败：自定义模型没有投影到上下文。
- 修复后该测试通过，确认模型 ID、显示名称进入上下文，Task 工具中不再出现旧名单。
- 新增单元回归覆盖排序去重、标签转义及不传入凭据、名单变更/清空/重试、稳定工具定义、设置优先级和 checkpoint 编解码去重。
- 压缩回归更新了预期消息结构，明确检查摘要后的子代理模型上下文与用户消息均存在。
- 新增 5 项单元及 1 项 transport 集成测试通过，服务端全量 338 项、Clippy（`-D warnings`）、格式及 diff 检查通过。工具说明变更对应的固定 schema 摘要已更新。最终自动化结果见 [证据记录](2026-10-08-issue449-evidence.json)。
